본드 런치 약속 시장, 개발자 인계서

수익원마다 그것을 걷는 코드가 어디에 있어야 하는지, 각 구성요소가 Web2의 무엇에 해당하는지, 데이터 모델과 수식과 테스트와 완료 조건까지 한 문서에 담았습니다. 수치와 규칙이 스펙과 충돌하면 이 문서가 우선합니다.

온체인 프로그램부터 읽기 수익 구조부터 읽기

토큰을 런치한 팀이 "러그 안 친다"는 약속 5가지에 자기 돈을 걸고, 홀더는 그 약속이 깨질 때 보상받는 보호를 산다.

보호 가격은 수요에 따라 자동으로 오르내리고, 6개월 동안 약속을 지킨 기록이 신용등급이 된다.

Web2로 한 줄

마켓플레이스 위에 붙는 에스크로 + 보증보험 모듈. 보험료는 서지 프라이싱, 이력은 신용점수.

우리가 아닌 것

런치패드가 아니다. 어디서 런치했든, 이미 런치된 토큰이든 위에 붙는 레이어다.

핵심 설계

보험사가 없다. 팀이 건 본드가 곧 지급 준비금이다. 그래서 2면 시장이고 콜드 스타트가 한 번이다.

처음 보는 개발자가 각 부품을 30초 안에 자리매김하도록 대응표를 먼저 둡니다.

수익 구조와 그것을 걷는 코드

수익원마다 "돈이 실제로 우리 계좌에 들어오려면 코드 어디에 무엇이 있어야 하는가"를 적었습니다. 등록 수수료는 받지 않습니다. 팀은 돈을 내는 게 아니라 겁니다.

수익원 1 · Take rate 보험료 수수료 10%

홀더가 낸 보험료의 10%. Airbnb 서비스 수수료와 같은 자리.

발생 buy_coverage 실행 순간. 정산을 기다리지 않는다.

개발 Protocol에 premium_fee_bps와 fee_vault. buy_coverage 안에서 10%는 fee_vault, 90%는 bond_vault로 두 갈래 전송. admin 전용 withdraw_fees. 인덱서에 일별 수수료 테이블.

수익원 2 · Settlement fee 슬래시 수수료 10%

파기 시 커버리지 지급 후 남은 본드의 10%. PayPal 분쟁 처리 수수료.

개발 resolve_epoch의 Breached 분기에서 remaining × 10%를 fee_vault로. 나머지 90%의 배분 비율을 Epoch에 기록하고 claim이 그 비율로 지급.

순서 커버리지 지급이 먼저, 수수료가 다음. 바뀌면 홀더 보상이 줄어 신뢰가 깨진다.

수익원 3 · Partner fee 런치패드 통합 0.5%

런치패드 경유 등록 시 본드의 0.5% 또는 월정액. 토스페이먼츠가 카페24에 붙는 구조.

개발 Launch에 partner 필드, register_launch에 partner_code 인자. 화이트리스트와 분배율은 v2. 필드만 미리 넣으면 마이그레이션이 없다.

수익원 4 · Data licensing 등급 API 구독 월정액

NICE가 은행에 신용조회 건당 과금하는 것과 같다. 6개월 이력이 쌓인 뒤 렌딩·지갑·애그리게이터 대상.

v1 공개 엔드포인트 3개와 배지 SVG, 인증 없음.

v2 API 키, 키별 rate limit, 사용량 집계, 무료 티어(배지)와 유료 티어(전체 이력) 분리.

원천 데이터는 전부 온체인에 있다. 우리가 파는 것은 편의와 SLA이지 독점 데이터가 아니다.

수익 흐름 한눈에

홀더 → buy_coverage → 보험료 100
                         ├─ 10 → fee_vault            (수익원 1)
                         └─ 90 → bond_vault           (팀 적립)

Breach → resolve_epoch → bond_vault 잔액
                         ├─ coverage_sold → 홀더      (claim)
                         └─ 나머지 R
                              ├─ R×10% → fee_vault    (수익원 2)
                              └─ R×90% → 홀더         (claim, pro-rata)

파트너 경유 register_launch → 본드 × 0.5%
                         ├─ 파트너 몫 → 파트너 지갑
                         └─ 우리 몫  → fee_vault      (수익원 3)

구현 규칙

활성 약속만 검사. remaining_accounts 인덱스는 플래그 순서로 고정. 전달 계정 주소는 등록 주소와 반드시 대조. 하나라도 위반이면 Breached. unlock_slot이 에포크 중간이면 그 에포크는 검사하지 않는다.

가격 공식 (서지 프라이싱)

u_bps  = coverage_sold × 10_000 / bond_balance
r_bps  = r_min + (r_max − r_min) × u_bps² / 10_000²
premium = amount × r_bps / 10_000
fee     = premium × premium_fee_bps / 10_000
to_bond = premium − fee
  • 전부 정수 연산. u_bps²는 u128. 나눗셈은 내림.
  • 검증값: u 0.3 → r_bps 180, u 0.8 → 978.
  • 구매 직전 u로만 계산한다. "장바구니에 담을 때 가격 고정". 구간 적분은 v2.
  • coverage_sold + amount > bond_balance면 거부. 좌석 초과 판매 금지.

정산 공식

Passed 돈이 움직이지 않는다. passed_epochs += 1, rate_sum_bps += closing_rate_bps. 6번째면 Completed.

Breached

remaining   = bond_balance − coverage_sold
slash_fee   = remaining × slash_fee_bps / 10_000
bonus_pool  = remaining − slash_fee
payout_per_unit = (coverage_sold + bonus_pool) × 1e6 / coverage_sold
claim: payout = amount × payout_per_unit / 1e6

마지막 청구자의 반올림 오차는 admin이 회수. coverage_sold == 0이면 bonus_pool 전액이 fee_vault로 간다.

상태 머신

Launch:  Active ──(6× Passed)──▶ Completed ──(withdraw_bond)──▶ [끝]
           └──(Breached)──▶ Breached ──(claim ×N)──▶ [끝]
Epoch:   Open ──(resolve, 전부 통과)──▶ Passed
           └──(resolve, 하나라도 위반)──▶ Breached

주문 상태 "결제완료 → 배송중 → 배송완료 / 환불"과 같다. 역방향 전이는 없다.

1분마다 end_slot ≤ 현재인 Open 에포크에 resolve_epoch, Passed면 이어서 open_epoch. 계정 목록은 Launch.covenants에서 조립. 멱등성은 온체인의 EpochAlreadyResolved가 보장한다.

테스트 계획

Anchor 테스트(litesvm 또는 bankrun). 두 경로를 끝까지 돌린다.

경로 A · 6개월 전부 Pass

  1. register(본드 50,000) → 홀더 3명 buy(합 40,000) → 보험료·수수료 검증
  2. slot 전진 → resolve Passed, passed_epochs = 1
  3. open_epoch ×5, 각각 Passed
  4. withdraw_bond = 50,000 + 적립 보험료
  5. fee_vault = 총 보험료의 10%

경로 B · 2개월째 트레저리 초과 인출

  1. 경로 A의 1~2
  2. open_epoch → buy → max_outflow 초과 전송
  3. resolve Breached, payout_per_unit 검증
  4. claim ×3 합계 = coverage_sold + bonus_pool (오차 ≤ 3)
  5. fee_vault 증가분 = remaining × 10%
  6. withdraw_bond 실패(LaunchNotCompleted)

경로 C · 에러 12종

각 에러 코드를 1회씩 유발한다.

경로 D · 가격 공식 단위값

u = 0, 0.3, 0.5, 0.8, 1.0에서 r_bps = 50, 180, 412, 978, 1500.

데모 3분

  1. 팀이 devnet에서 토큰 런치 후 본드 5,000 USDC 예치, 약속 5종 켬. 20초
  2. 지갑 3개가 보호 구매. 곡선 위 점이 오르는 것을 상세에서 보여줌. 30초
  3. 10분 에포크 종료. 크랭커 로그에 resolve → PASS. 보험료가 본드에 쌓임. 20초
  4. 2번째 에포크 중 팀이 트레저리 초과 인출. 약속 3이 빨간색으로. 15초
  5. resolve → BREACH. 홀더 3개 지갑 잔고 증가, 카드가 D로. 30초
  6. 6개월 지킨 런치의 AAA 배지와 JSON 응답. 20초

Anchor 0.31+, Solana CLI v3, create-solana-dapp nextjs-anchor, Helius devnet RPC, Node 20 + Postgres/SQLite, litesvm 또는 bankrun. USDC는 우리가 만든 devnet 테스트 민트, 주소는 Protocol에 저장.
