# 프로젝트 소개서 v2: 팀이 자기 돈을 건 런치 약속을 시장이 가격 매긴다

작성일: 2026-09-09
상태: 해커톤 MVP 스펙 v2 (선발 가능성 기준으로 조정)

---

## 0. v1에서 무엇을 바꿨고 왜 바꿨나

| v1 (직전 안) | v2 (조정안) | 이유 |
|---|---|---|
| 모든 Solana 프로젝트의 월간 신용 시장 | **토큰 런치 직후 6개월의 "약속(covenant) 시장"** | 구매자가 지금 존재하는 곳으로 좁힘. 런치 직후 홀더는 러그가 가장 무서운 시점에 있고, 팀은 러그가 아니라는 신호를 가장 절실히 원함 |
| 프로젝트 / 인수자 / 보호 구매자 3면 시장 | **팀의 본드가 곧 인수 자본. 2면 시장** | 콜드 스타트 3회를 1회로. 제3자 인수자는 v2에서 본드 용량 초과분에만 추가 |
| 요건 = 트레저리 잔고 등 "상태" | **약속 = 러그 체크리스트 5종(권한, 민트, 트레저리 유출, 팀 언락, LP 락)** | Solana 유저 전원이 이미 아는 언어. RugCheck가 "오늘 참인 것"을 보여준다면 우리는 "내일도 참일 것에 팀이 돈을 걸게" 함 |
| 등급이 상품, 시장은 장치 | **런치 보호가 상품, 등급은 누적 산출물** | 지금 돈을 내는 사람(홀더)과 지금 유통해 줄 사람(런치패드)이 생김. 등급은 6개월 뒤 자연히 자산이 됨 |
| 프로토콜 수익이 운용 수익 수수료 중심 | **보험료 수수료 + 슬래시 수수료 + 런치패드 통합 수수료** | 운용 수익은 남의 프로토콜 의존이고 작음. 보험료는 우리 시장에서 나옴 |

프로젝트 신용등급이라는 최종 목표는 그대로입니다. 순서를 바꿨을 뿐입니다. 런치 약속 이력 → 운영 약속(매출, 런웨이) → 렌딩·런치패드가 읽는 등급.

---

## 1. 한 문장

**토큰을 런치하는 팀이 러그 방지 약속 5가지에 자기 돈을 걸고, 홀더는 그 약속이 깨질 확률을 시장에서 사고팔며, 6개월간 약속을 지킨 이력이 온체인 신용등급이 된다.**

심사위원용 60초 버전: "RugCheck는 오늘 참인 것을 보여줍니다. 우리는 팀이 내일도 참일 것에 돈을 걸게 하고, 시장이 그 확률에 가격을 매기게 합니다."

---

## 2. 왜 이 형태가 뽑히는가

- **Colosseum RFP 두 개의 교차점.** "Onchain transparency ratings(정상 프로젝트와 스캠 구분)" + "Permissionless prediction markets". 둘 다 Cypherpunk 때 Colosseum이 직접 적은 문장입니다.
- **예측시장 레이어 패턴에 부합.** 3개 코호트 연속 선발된 팀은 전부 예측시장 위의 레이어였습니다. 이 안은 "약속 이행"이라는 새 원천 시장을 만듭니다.
- **구매자가 지금 있음.** 런치 직후 홀더. Solana에서 하루 수만 개 토큰이 나오고, MetaDAO·Meteora DBC·Believe 같은 "진지한 런치" 채널만 잡아도 월 수백 건입니다.
- **유통 채널이 명확.** 런치패드는 "본드 걸린 런치" 배지를 차별화 기능으로 원합니다. MetaDAO는 이미 "Solana 토큰 신뢰 위기"를 자기 문제로 정의했습니다.
- **데모가 60초 안에 이해됨.** 팀이 트레저리를 빼돌리는 순간 프로그램이 본드를 슬래시해 홀더에게 지급하는 장면 하나면 됩니다.
- **오라클이 없음.** 약속 5종 전부 프로그램이 계정을 직접 읽어 판정합니다. "누가 진실을 정하는가"에 대한 답이 "아무도 아니다, 체인이 정한다"입니다.

## 3. 참여자와 돈의 흐름

| 참여자 | 하는 일 | 얻는 것 |
|---|---|---|
| **런치 팀** | 약속 5종 선언, 본드(USDC) 예치 6개월 | "본드 걸린 런치" 배지, 약속 지킬 때마다 보험료 수입, 6개월 뒤 신용등급 |
| **홀더 (보호 구매자)** | 보험료 내고 커버리지 구매 | 약속 파기 시 커버리지 전액 + 남은 본드 배분. 손실 상한 = 보험료 |
| **크랭커** | 에포크 종료 후 정산 호출 | 소액 보상 |
| **런치패드** | 런치 플로우에 본드 예치 단계 임베드 | 러그 방지 배지, 통합 수수료 배분 |
| **등급 소비자 (v2)** | 등급 계정 읽기 | 프로젝트 리스크를 숫자 하나로 |

핵심 규칙:
- **팀의 본드가 Pass 측 자본입니다.** 별도 인수자 없이 시장이 열립니다.
- **팀은 자기 시장의 Default 측을 살 수 없습니다.**
- **약속은 팀만 깰 수 있는 것으로 한정합니다.** 홀더가 약속 파기를 유도할 방법이 없습니다.

## 4. 약속 5종 (전부 프로그램이 직접 검증)

| # | 약속 | 검증 | 읽는 계정 |
|---|---|---|---|
| 1 | 업그레이드 권한이 선언한 멀티시그(또는 null)에서 바뀌지 않음 | ProgramData의 upgrade_authority 비교 | 프로그램의 ProgramData |
| 2 | 민트 권한 null 유지 (추가 발행 없음) | Mint의 mint_authority == None | 토큰 Mint |
| 3 | 트레저리 유출이 에포크당 상한 이하 | 에포크 시작 스냅샷 − 현재 잔고 ≤ 상한 | 트레저리 토큰 계정 |
| 4 | 팀·투자자 지갑에서 언락 일자 전 반출 없음 | 스냅샷 잔고 ≤ 현재 잔고 | 지정 토큰 계정들 |
| 5 | 초기 LP가 락 기간 동안 유지됨 | 지정 LP 토큰 계정 잔고 ≥ 스냅샷 | LP 토큰 계정 (Meteora DAMM v2 포지션 포함) |

팀은 5종 중 원하는 것을 고르고 파라미터를 정합니다. 많이 걸수록 시장이 낮은 보험료율을 매기고, 그것이 곧 좋은 등급입니다.

---

## 5. 에포크 한 바퀴 (30일 × 6회)

```
런치일   팀: 약속 선택 + 본드 예치 (예: 조달액의 10% = 50,000 USDC)
         프로그램: 약속 5종 기준값 스냅샷
D+0~30   홀더: 커버리지 구매. 보험료율 = 곡선(팔린 커버리지 / 본드)
D+30     누구나 resolve 호출 → 약속 5종 검증
         PASS:    보험료(90%)를 팀 본드에 적립, 다음 에포크 오픈
         DEFAULT: 커버리지를 홀더에게 지급, 남은 본드의 90%를 커버리지 보유자에 배분, 시장 종료
D+180    6 에포크 PASS → 본드 + 누적 보험료 반환, 등급 계정 확정
```

### 보험료율 곡선

```
월 보험료율 r(u) = r_min + (r_max − r_min) × u²
u = 팔린 커버리지 / 본드 잔액   (0 ≤ u ≤ 1)
기본값 r_min 0.5%/월, r_max 15%/월
```

보호 수요가 몰릴수록 u와 r이 오릅니다. r이 시장이 매긴 월간 파기 확률이고, 6개월 평균 r이 등급의 핵심 입력입니다.

## 6. 수익 구조

### 6.1 수익원

| # | 수익원 | 요율 | 발생 시점 | 성격 |
|---|---|---|---|---|
| 1 | **보험료 수수료** | 보험료의 10% | 커버리지 구매 시 | 거래량 비례, 매월 |
| 2 | **슬래시 수수료** | 파기 시 남은 본드의 10% | 파기 정산 시 | 이벤트성 |
| 3 | **런치패드 통합** | 본드 예치액의 0.5% 또는 월 정액 | 런치 시 | B2B, 유통 채널이 곧 매출 |
| 4 | **등급 API** | 월정액 (렌딩·지갑·애그리게이터) | 6개월 후 | B2B, 장기 |

팀에게 등록 수수료를 받지 않습니다. 팀은 돈을 내는 게 아니라 돈을 겁니다. 약속을 지키면 오히려 보험료를 법니다. 이것이 팀이 들어오는 이유입니다.

### 6.2 런치 1건 숫자 예시

가정: 조달 500,000 USDC, 본드 50,000 USDC(10%), 6개월. 홀더 보호 수요는 1개월차 u = 0.8에서 시작해 매월 0.15씩 감소.

| 월 | u | r | 보험료 | 프로토콜(10%) | 팀 적립(90%) |
|---|---|---|---|---|---|
| 1 | 0.80 | 9.78% | 3,912 | 391 | 3,521 |
| 2 | 0.65 | 6.63% | 2,154 | 215 | 1,939 |
| 3 | 0.50 | 4.13% | 1,031 | 103 | 928 |
| 4 | 0.35 | 2.28% | 398 | 40 | 358 |
| 5 | 0.20 | 1.08% | 108 | 11 | 97 |
| 6 | 0.10 | 0.65% | 32 | 3 | 29 |
| 합계 | | | 7,635 | **764** | **6,871** |

**6개월 전부 PASS**: 팀은 본드 50,000 + 6,871 회수 (본드 대비 연환산 약 27%). 홀더는 보험료 7,635 소멸(보호 비용). 프로토콜 764 + 런치패드 통합 250 = **약 1,014 USDC / 런치**.

**2개월차 파기** (트레저리 유출 상한 초과): 커버리지 32,500(u 0.65 × 50,000)을 홀더에게 지급. 남은 본드 17,500 + 적립 보험료 5,460 = 22,960 중 10%인 2,296 프로토콜, 90%인 20,664를 커버리지 보유자에게 추가 배분. 홀더 총 수령 53,164, 투입 보험료 6,066 대비 약 8.8배. 프로토콜 606 + 2,296 = **약 2,902 USDC**.

### 6.3 규모 추정

| 월 신규 본드 런치 | 평균 본드 | 월 프로토콜 수익 (파기율 5%) |
|---|---|---|
| 20 | 30k | 약 9k USDC |
| 100 | 40k | 약 60k USDC |
| 300 | 50k | 약 220k USDC |

v1과 달리 수익이 "우리 시장의 보험료"에서 나오고, 런치패드 통합이 유통과 매출을 동시에 만듭니다. 등급 API는 보너스입니다.

### 6.4 각 참여자가 들어오는 이유

- **팀**: 러그가 아니라는 신호를 돈으로 증명 + 약속 지키면 보험료 수입. 본드는 돌려받습니다.
- **홀더**: 런치 직후 가장 무서운 90일을 보험료 몇 %로 보호. 파기 시 수 배 페이아웃.
- **런치패드**: "본드 걸린 런치" 배지가 자기 플랫폼 런치의 신뢰도를 올림. 통합 수수료 배분.

## 7. 무엇을 개발해야 하는가

### 7.1 전체 구조

```
┌────────────────────────────────────────────────────────┐
│  프론트 (Next.js): 런치 목록 · 런치 상세 · 보호 구매 · 팀 등록  │
│  + 런치패드 임베드용 위젯 (배지 + 본드 현황)                    │
└──────────────┬────────────────────────────┬────────────┘
               │ RPC / 지갑                  │ REST
┌──────────────▼─────────────┐  ┌───────────▼────────────┐
│  온체인 프로그램 (Anchor)      │  │  인덱서 + 등급 API (TS)   │
│  Launch · Epoch · Coverage   │  │  이력 → 등급 → JSON/SVG   │
│  register · open · buy ·     │  └────────────────────────┘
│  resolve · claim · withdraw  │
└────────────────────────────┘
```

v1에 있던 제3자 인수 풀과 수익 vault는 **제거**했습니다. 팀 본드가 자본이므로 필요 없습니다. 개발량이 약 30% 줄고, 데모 이야기가 단순해집니다.

### 7.2 온체인 프로그램 (비중 55%)

**계정 (PDA)**

| 계정 | 키 | 주요 필드 |
|---|---|---|
| `Protocol` | 싱글턴 | admin, 수수료 요율, r_min, r_max, 에포크 길이, 총 에포크 수 |
| `Launch` | mint | team, 약속 5종 파라미터와 활성 플래그, 본드 잔액, 적립 보험료, 현재 에포크, 상태, **등급 필드**(passed_epochs, avg_rate_bps, breached_at) |
| `Epoch` | launch + index | 시작·종료 slot, 스냅샷 5종, coverage_sold, premium_collected, 결과 |
| `Coverage` | epoch + wallet | 커버리지 금액, 낸 보험료, claim 여부 |

`Launch` 계정이 온체인 등급 어테스테이션입니다.

**인스트럭션 6개**

| 순서 | 인스트럭션 | 호출자 | 하는 일 |
|---|---|---|---|
| 1 | `register_launch` | 팀 | 약속 선택·파라미터, 본드 USDC 예치, 1차 스냅샷 |
| 2 | `open_epoch` | 누구나 | 이전 에포크 Pass 확인 후 새 스냅샷, Epoch 생성 |
| 3 | `buy_coverage` | 홀더 | u로 r 계산, 보험료 징수(10% 분리), Coverage 기록, u ≤ 1 강제 |
| 4 | `resolve_epoch` | 누구나 (종료 후) | 약속 5종 검증 → Passed/Breached, 배분 비율 확정 |
| 5 | `claim` | 홀더 | Breached 시 커버리지 + 잔여 본드 배분 수령 |
| 6 | `withdraw_bond` | 팀 | 전 에포크 Pass 후 본드 + 적립 보험료 회수 |

**설계 결정**
- 어떤 약속이든 하나라도 깨지면 Breached. 부분 파기 가중치는 v2.
- `buy_coverage`의 r은 구매 직전 u 기준. 구간 적분은 v2.
- 약속 5번(LP 락)은 v1에서 "LP 토큰 계정 잔고 ≥ 스냅샷"의 단순형으로. Meteora DAMM v2 포지션 NFT 직접 읽기는 시간 남으면.
- 에포크 길이는 slot 파라미터. 데모는 10분 에포크.

### 7.3 인덱서 + 등급 API (비중 15%)

```
score = 50 × passed_epochs / 6
      + 35 × (1 − avg_rate / r_max)
      + 15 × min(활성 약속 수, 5) / 5
AAA ≥ 85, AA ≥ 75, A ≥ 65, BBB ≥ 55, BB ≥ 45, B ≥ 35, CCC ≥ 20, 파기 = D
```

엔드포인트: `GET /launches`, `GET /launches/:mint`, `GET /launches/:mint/badge.svg`. 배지 SVG가 런치패드·트위터에 박히는 유통 도구입니다.

### 7.4 프론트 4화면 + 위젯 (비중 25%)

1. **런치 목록**: 배지 등급, 현재 r, 본드 잔액, 이용률, 지킨 에포크 수.
2. **런치 상세**: 약속 5종과 현재 값(실시간 계정 읽기), 에포크 타임라인, 곡선 위 현재 위치.
3. **보호 구매**: 커버리지 입력 → 보험료·파기 시 수령액 표시 → 구매.
4. **팀 등록**: 민트, 프로그램, 트레저리, 팀 지갑, LP 계정, 본드 금액.
5. **임베드 위젯**: 런치패드 페이지에 iframe으로 들어가는 배지 + "보호 구매" 버튼.

### 7.5 데모 시나리오 (3분 영상의 뼈대)

1. 팀이 devnet에서 토큰을 런치하고 본드 5,000 USDC를 걸며 약속 5종을 켠다. (20초)
2. 홀더 지갑 세 개가 커버리지를 사고, 보험료율이 곡선을 따라 오르는 것을 보여준다. (30초)
3. 10분 에포크가 끝나고 크랭커가 resolve. PASS. 보험료가 팀 본드에 적립. (20초)
4. 2번째 에포크 중 팀 지갑이 트레저리에서 상한 초과 인출. (15초)
5. resolve → BREACHED. 홀더 세 지갑에 커버리지와 잔여 본드가 들어오고, 런치 카드가 D 등급으로 바뀐다. (30초)
6. 같은 화면에 6개월 지킨 다른 런치의 AAA 배지와 등급 API 응답을 보여준다. (20초)

## 9. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 팀이 본드 낼 USDC가 없음 | 본드 최소액을 낮게(조달액 5% 또는 5,000 USDC). 런치패드가 조달액에서 자동 예치하는 플로우가 정답이라 통합이 핵심 |
| 보험 규제 | "약속 시장"으로 명명, 미국 IP 차단, 팀의 Default 참여 금지 명문화. 페이아웃은 팀 자산에서 나가므로 제3자 보험 인수와 구조가 다름 |
| 약속이 형식적일 수 있음 | 시장이 알아서 낮은 r을 매김. 약속 수와 파라미터 엄격도가 등급 산식에 들어감 |
| 홀더가 보험료를 안 냄 | 런치 후 30일이 수요 피크. 위젯을 런치 페이지에 박아 구매 마찰을 없앰 |
| RugCheck·GoPlus와 비교 | 그들은 정적 스캔. 우리는 미래 약속 + 돈 + 시장 가격. 보완재로 포지셔닝 |

## 10. 팀이 정해야 할 것

1. 본드 최소액과 조달액 대비 비율.
2. 부분 파기(예: 트레저리 상한 소폭 초과)를 전액 슬래시로 볼지 가중치를 둘지. v1은 전액.
3. 6개월 후 "운영 약속"(월 온체인 매출 ≥ X 등)으로 확장할지, 런치 약속만 반복할지.
4. 첫 통합 런치패드 후보: MetaDAO(큐레이션, USDC 조달, 신뢰 서사 일치), Meteora DBC(퍼미션리스, 물량), Believe.
